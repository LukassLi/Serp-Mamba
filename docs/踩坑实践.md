```bash
conda create -n Serp-mamba python=3.10 -y
```

## 第二步：安装 PyTorch

**必须统一为 CUDA 12.1**，因为 PyTorch 2.1.2 没有官方 cu122 预编译包。

```bash
pip install torch==2.1.2 torchvision==0.16.2 torchaudio==2.1.2 --index-url https://download.pytorch.org/whl/cu121
```

**坑点说明**：README 中要求下载 `cu122` 版本的 mamba_ssm/causal_conv1d，但与 PyTorch cu121 不匹配。**全部统一为 cu121 是最稳妥方案**。

## 第四步：清理并修正 requirements.txt

原始 `requirements.txt` 存在多个问题，必须逐一手动修正：

| 问题 | 原始内容 | 修正方式 |

## 第六步：单独安装 inplace_abn（可以跳过）

这个包与新版 setuptools 不兼容，无法通过普通方式安装。

### 解决方法
**临时降级 setuptools → 编译安装 → 恢复新版：**

```bash
# 1. 临时降级
pip install setuptools==59.5.0
# 2. 编译安装
pip install --no-build-isolation inplace_abn==1.1.0
# 3. 恢复新版
pip install setuptools==82.0.1
```

**坑点说明**：
- 官方 PyPI 的 `1.1.0` 包元数据有 bug（版本号显示为 `0.0.0`），pip 会拒绝安装。
- 临时降级 setuptools 可以规避编译时的 `pkg_resources` 缺失问题。
- 如果项目不涉及模型训练，可以跳过此包。

---

## 第七步：安装剩余依赖

确认 `requirements.txt` 已按上表修正后，运行：

```bash
pip install --no-build-isolation -r requirements.txt
```

**`--no-build-isolation` 参数至关重要**：让所有需要编译的包使用当前环境的 torch 和 setuptools，避免隔离环境找不到依赖。

## 核心经验总结

| 坑点类型 | 现象 | 根本原因 | 解决原则 |
|:---|:---|:---|:---|
| **CUDA 版本不匹配** | GPU 代码无法运行或安装失败 | README/whl/PyTorch 三者不统一 | 统一为 cu121 |
| **源码编译失败** | `ModuleNotFoundError: No module named 'torch'` | pip 构建隔离环境找不到依赖 | 使用 `--no-build-isolation` |
| **PyPI 包版本不存在** | `No matching distribution found` | 作者写错版本号或包名 | 去掉版本号或更正包名 |
| **依赖版本冲突** | `conflicting dependencies` | 直接锁定版本过于严格 | 删除版本锁，让 pip 自动协调 |
| **setuptools 兼容性** | `No module named 'pkg_resources'` | 旧包不兼容新版 setuptools | 升级工具链 + 临时降级编译 |
| **.whl 与 PyPI 冲突** | 手动装好的包被覆盖或降级 | requirements.txt 包含旧版本号 | 手动安装的包从文件中删除 |
